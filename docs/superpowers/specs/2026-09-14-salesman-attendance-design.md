# Salesman Activity-Driven Attendance Design

**Date:** 2026-09-14  
**Status:** Approved  

---

## 1. Overview & Business Context

Titan ERP previously excluded salesmen from attendance tracking (`isSalesman = false` filter), meaning salesmen did not punch in at terminals and were bypassed during payroll attendance verification.

Field salesmen operate dynamically: they do not sit at a desk or punch timecards, but their operational actions in the field (delivering orders and performing credit recoveries) indicate presence. This design introduces **Activity-Driven Attendance for Salesmen**, automatically marking them present when field tasks occur, highlighting inactive days as `Pending / Review` for HR, and enforcing attendance completeness before payroll can be run.

---

## 2. Core Requirements

1. **Approved Attendance Triggers (Field Activity):**
   * **Order Delivery / Fulfillment:** Marked `delivered` with `fulfilledBySalesmanId` via [`fulfillOrderFn`](file:///home/abdul-rehman/Projects/titan-new/src/server-functions/sales/orders-fn.ts#L270).
   * **Credit Recovery Visits / Attempts:** Logged in [`creditRecoveryAttempts`](file:///home/abdul-rehman/Projects/titan-new/src/server-functions/sales/credit-recovery-fn.ts#L431) with `assignedToId`.
   * *Invoices Excluded:* Billing and invoice creation are explicitly **not** triggers because invoices may be generated by office accountants without the salesman being present.

2. **Attendance Record Format:**
   * `status`: `"present"`
   * `entrySource`: `"salesman_activity"`
   * `dutyHours`: `standardDutyHours` (from employee settings, default `8.00`)
   * `checkIn`: `null` (no timestamp punches)
   * `checkOut`: `null` (no timestamp punches)

3. **Auto-Rollback & Reversal:**
   * If an order fulfillment or recovery attempt is deleted/cancelled and 0 approved activities remain for that date, any auto-generated `salesman_activity` record is automatically deleted.
   * Auto-rollback will **never** delete manual HR records.

4. **HR Authority & Guardrails:**
   * **HR Precedence:** If HR manually marks a date (e.g. `Leave`, `Holiday`, `Absent`, or manual `Present`), activity sync will **never** overwrite HR's decision.
   * **Weekly Rest Days:** Salesmen with no activity on their weekly rest day display as `Rest Day`.

5. **HR Daily Attendance Dashboard:**
   * A dedicated **"Salesmen"** tab is added to [`attendance-list-table.tsx`](file:///home/abdul-rehman/Projects/titan-new/src/components/hr/attendance/attendance-list-table.tsx#L635) alongside "Standard Staff" and "Order Bookers".
   * Displays employee information, attendance status badge (`Present (Field Activity)`, `Rest Day`, `Leave`, `Absent`), activity counter summary (e.g. `2 Deliveries, 1 Recovery`), and quick-action buttons for HR manual overrides.
   * Unresolved working days with no activity display an amber **`Pending / Review`** badge.

6. **Payroll Integration:**
   * In [`core.ts`](file:///home/abdul-rehman/Projects/titan-new/src/server-functions/hr/payroll/core.ts#L71-L78), salesmen are no longer exempted from missing attendance validation.
   * Any `Pending / Review` days in a pay period will block payroll finalization until HR confirms or marks the status.

7. **Employee Forms:**
   * In [`add-employee-form.tsx`](file:///home/abdul-rehman/Projects/titan-new/src/components/hr/employees/add-employee-form.tsx#L594) and [`edit-employee-form.tsx`](file:///home/abdul-rehman/Projects/titan-new/src/components/hr/employees/edit-employee-form.tsx), update description text from *"Excluded from attendance"* to *"Attendance is tracked from deliveries and recoveries."*

## 3. Architecture & Data Flow

### 3.1 Attendance Sync Engine (`salesman-attendance-sync.ts`)
A dedicated module [`src/server-functions/sales/salesman-attendance-sync.ts`](file:///home/abdul-rehman/Projects/titan-new/src/server-functions/sales/salesman-attendance-sync.ts):
* Accepts `{ tx, salesmanId, businessDate }`.
* Resolves `salesmen.employeeId` and `employees.standardDutyHours`.
* Queries existing attendance for that date. If existing row has `entrySource !== "salesman_activity"` (e.g. `"manual"`), it exits early without modifying.
* Counts active activities for that date:
  * Count of fulfilled orders for `salesmanId` on `businessDate`.
  * Count of recovery attempts for `salesmanId` on `businessDate`.
* If `totalActivities > 0`:
  * Inserts or upserts `attendance` with `status: "present"`, `entrySource: "salesman_activity"`, `dutyHours: standardDutyHours`.
* If `totalActivities === 0`:
  * If existing row exists and `entrySource === "salesman_activity"`, deletes the row.

## 4. UI & Dashboard Layout

In [`src/components/hr/attendance/attendance-list-table.tsx`](file:///home/abdul-rehman/Projects/titan-new/src/components/hr/attendance/attendance-list-table.tsx):
* Split employees into 3 tabs:
  * `standardData = data.filter(e => !e.isOrderBooker && !e.isSalesman)`
  * `orderBookerData = data.filter(e => e.isOrderBooker)`
  * `salesmanData = data.filter(e => e.isSalesman)`
* For the Salesmen table:
  * **Employee:** Avatar, Full Name, Code.
  * **Status:** 
    * If rest day: `<RestDayBadge />`
    * If manual HR row: `<StatusBadge />`
    * If activity present: Green `Present` badge with field indicator
    * If no record on working day: `<PendingReviewBadge />`
  * **Activity Column:** e.g. `2 Deliveries, 1 Recovery` (or `—` if none).
  * **Action Column:** Edit / Manual Override dialog trigger.
